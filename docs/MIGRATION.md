# Importing the v1 data

Optional. Do this only if you want the new deployment to start with the
original rocks and accounts instead of empty.

The old passwords were stored in plaintext behind a credential that has been
public since 2024. Treat every one of them as known to strangers. The point of
importing is continuity of the rock registry, not preserving security that was
never there.

---

## 0. Does the data still exist?

Atlas pauses a free M0 cluster after 60 days idle, and eventually deletes a
paused one. This project has been dormant for a while, so check before planning
around it: open the Atlas project and look at the cluster. If it says
**Paused**, resume it; that takes a few minutes and the data is intact. If the
cluster is gone, so is the data, and there is nothing to recover.

---

## 1. Make a temporary export user

Do **not** reuse `hector_admin`. That credential is in the git history of a
public repository; it needs deleting, not using.

In Atlas:

1. **Database Access → Add New Database User**
   - Username `tmp_export`, autogenerated password, copy it somewhere.
   - Built-in role: **Only read any database**.
2. **Network Access → Add IP Address → Add Current IP Address.**
3. Once the export is done, delete this user and remove the IP entry.

While you are in Database Access: delete `hector_admin` now if you have not
already.

---

## 2. Dump

`mongodump` ships inside the official mongo image, so there is nothing to
install locally.

```bash
docker run --rm -v "$PWD:/out" mongo:8 mongodump \
  --uri "mongodb+srv://tmp_export:PASSWORD@hector.lnv1yey.mongodb.net/test" \
  --gzip --archive=/out/hector-v1.archive.gz
```

If the password contains `@`, `:`, `/` or `?`, percent-encode it or the URI
parser will misread it. Autogenerated Atlas passwords are usually safe.

> **Which database?** The old connection string had no database name in the
> path, so Mongoose used the driver default, `test`. Confirm before dumping:
>
> ```bash
> docker run --rm mongo:8 mongosh \
>   "mongodb+srv://tmp_export:PASSWORD@hector.lnv1yey.mongodb.net/" \
>   --quiet --eval 'db.getMongo().getDBNames().forEach(n => print(n))'
> ```
>
> If the collections live somewhere other than `test`, use that name in the
> `--uri` above and in `--nsFrom` below.

Check what you got:

```bash
docker run --rm -v "$PWD:/out" mongo:8 \
  mongorestore --gzip --archive=/out/hector-v1.archive.gz --dryRun -v 2>&1 | grep -i 'found collection'
```

## 3. Restore into the Pi

```bash
scp hector-v1.archive.gz pi@raspberrypi.local:~/HECTOR/
```

Then on the Pi, in `~/HECTOR`:

```bash
docker compose cp hector-v1.archive.gz mongo:/tmp/v1.gz

docker compose exec mongo mongorestore \
  --username "$MONGO_ROOT_USERNAME" --password "$MONGO_ROOT_PASSWORD" \
  --authenticationDatabase admin \
  --gzip --archive=/tmp/v1.gz \
  --nsFrom 'test.*' --nsTo 'hector.*'
```

`--nsFrom/--nsTo` is what moves the collections out of the old `test` database
into `hector`, which is where the API looks. Without it the restore succeeds and
the site stays empty, which is a confusing five minutes.

Verify:

```bash
docker compose exec mongo mongosh -u "$MONGO_ROOT_USERNAME" -p "$MONGO_ROOT_PASSWORD" \
  --authenticationDatabase admin --quiet \
  --eval 'db.getSiblingDB("hector").users.countDocuments({})' \
  --eval 'db.getSiblingDB("hector").rocks.countDocuments({})'
```

## 4. Convert to the v2 shape

The restored documents are still v1 shaped: plaintext `password` fields, no
`createdBy` on rocks, no unique index on `username`. The API will not accept
them as they stand: a v1 user has no `passwordHash`, so login fails for
everyone.

```bash
npm run migrate:v1 -- --dry-run   # reports what it would change, writes nothing
npm run migrate:v1
docker compose restart api
```

What it does:

| Collection | Change                                                              |
| ---------- | ------------------------------------------------------------------- |
| `users`    | `password` (plaintext) → `passwordHash` (bcrypt), old field removed |
| `users`    | `createdAt` / `updatedAt` backfilled to 2024-05-01                  |
| `rocks`    | missing `owner` key → `owner: null`                                 |
| `rocks`    | `createdBy` backfilled from `owner` where there is one              |
| both       | indexes synced, which is what builds the unique `username` index    |

It is idempotent; running it twice does not re-hash anything.

**Existing passwords keep working.** The v2 complexity rules are enforced at
registration, not at login, so an old password that would be rejected by the
signup form still authenticates fine.

If it reports duplicate usernames it stops before building the unique index and
names them; resolve those by hand in `mongosh` and re-run.

---

## 5. Clean up

```bash
rm hector-v1.archive.gz          # on both machines
docker compose exec mongo rm /tmp/v1.gz
```

In Atlas: delete the `tmp_export` user, remove the IP allowlist entry, and, if
you are done with the cluster entirely, terminate it.

That archive holds every account's password in the clear. It should not sit in
your Downloads folder or your shell history.

## Testing this before you trust it

`backend/tests/migration.test.js` seeds a database in the exact v1 shape, runs
the migration, and asserts that an imported account can still sign in with its
original password, that no plaintext survives anywhere, that a released legacy
rock reads as adoptable, and that a second run changes nothing.

```bash
docker compose -f docker-compose.dev.yml up -d
TEST_MONGODB_URI=mongodb://localhost:27017/hector-test npm test
```

Rehearsing on a copy first is cheap:

```bash
# restore into a scratch database, migrate, poke at it, drop it
docker compose exec mongo mongorestore ... --nsFrom 'test.*' --nsTo 'rehearsal.*'
MONGODB_URI="mongodb://user:pass@localhost:27017/rehearsal?authSource=hector" \
  npm run migrate:v1 -- --dry-run
```
